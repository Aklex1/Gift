# Gift — торговый бот перепродажи подарков Telegram

Система поиска, оценки и перепродажи подарков Telegram с бюджетными
лимитами, управляемым риском и полным журналом операций.

Построена по ТЗ из аудита от 01.09.2026: capability-aware адаптеры,
атомарный бюджетный ledger, execution saga, оценка с учётом комиссий,
модель режимов SAFE/SEMI/AUTO.

---

## Быстрый старт

```bash
# на сервере, от root
BRANCH=claude/telegram-gift-resale-bot-p74jn7
git clone -b "$BRANCH" https://github.com/Aklex1/Gift.git /opt/gift
BRANCH="$BRANCH" bash /opt/gift/deploy/install.sh

# вписать ключи
nano /opt/gift/.env          # BOT_TOKEN, OWNER_IDS, TG_API_ID, TG_API_HASH

# авторизовать торговый аккаунт (спросит код из Telegram)
gift-cli login

# проверить и запустить
gift-cli doctor
systemctl enable --now gift-bot gift-web gift-worker
```

**Какие ключи нужны и где их взять — [docs/SETUP.md](docs/SETUP.md).**

## Как это работает

```
   сканер            оценка              исполнитель          портфель
 ┌─────────┐      ┌───────────┐      ┌────────────────┐    ┌──────────┐
 │ поиск   │─────▶│ ROI после │─────▶│ резерв бюджета │───▶│ позиция  │
 │ лотов   │      │ комиссий  │      │ покупка        │    │ листинг  │
 │ история │      │ риск 0-100│      │ сага исходов   │    │ репрайс  │
 └─────────┘      └───────────┘      └────────────────┘    │ продажа  │
                        │                     │            │ PnL      │
                        ▼                     ▼            └──────────┘
                  отсев убыточных       kill switch,
                  и рискованных         лимиты, режимы
```

Ключевые свойства:

- **Деньги резервируются до внешнего вызова.** Параллельные стратегии
  не могут вместе превысить общий потолок.
- **Таймаут не приводит к повторной покупке.** Неизвестный исход
  переходит в статус UNKNOWN и разрешается сверкой с площадкой.
- **ROI считается после комиссий.** Покупка за 850 и продажа за 1000
  при комиссии 20% распознаётся как убыток.
- **Автономный режим только для официального API.** Приватные
  коннекторы без SLA не допускаются в AUTO ни при каких настройках.

## Площадки

| Площадка | Чтение | Покупка | Статус |
|---|---|---|---|
| **Telegram** (MTProto) | да | **да** | `supported` — официальный API |
| Portals | да* | нет | `experimental` — приватный API |
| MRKT | да* | нет | `experimental` — приватный API |
| Tonnel | да* | нет | `experimental` — приватный API |
| Getgems | да* | нет | `experimental` — публичный API, write требует подписи кошельком |

\* при наличии токена; токены протухают, бот это переживает.

Торговля идёт на официальном маркете Telegram. Остальные площадки —
источник рыночных цен для оценки. Так решено осознанно: без
партнёрского доступа write-операции в приватный API — неуправляемый
риск потери средств.

---

## Режимы

| Режим | Что делает |
|---|---|
| `SAFE` | только находит и показывает; ни одного write-вызова |
| `SEMI` | покупает после явного подтверждения владельцем в боте |
| `AUTO` | торгует сам — только Telegram, только в пределах лимитов, при выключенном kill switch |

Глобальный режим в `.env` ограничивает стратегии сверху: если система
в SAFE, отдельная стратегия в AUTO не уйдёт.

| Кнопка / команда | Назначение |

| 🔎 Кандидаты | найденные возможности с ROI и обоснованием |

### CLI

```bash
gift-cli doctor      # проверка конфигурации
gift-cli login       # авторизация торгового аккаунта
```

установщиком (`cat /var/lib/gift/.webpass`).

## Архитектура

```
app/
  adapters/      контракт площадки + реализации
    base.py           capability-контракт, DTO, классы ошибок
    telegram_gateway  одна MTProto-сессия, очередь, FloodWait-пейсинг
    telegram_mtproto  официальный resale-маркет: поиск, покупка, листинг
    portals/mrkt/tonnel/getgems   чтение цен внешних площадок
    ton.py            баланс TON, только чтение
  services/
    budget.py         атомарный ledger: резерв, списание, лимиты
    saga.py           PLANNED→RESERVED→SUBMITTED→…→RECONCILED
    marketdata.py     медиана с отсевом выбросов, confidence, скорость продаж
    valuation.py      ROI после комиссий, risk score 0-100
    strategy.py       фильтры, бюджеты, приоритеты
    scanner.py        обход рынков и отбор кандидатов
    executor.py       покупка с предохранителями
    portfolio.py      позиции, PnL, сверка инвентаря
    repricer.py       лестница снижения цены до пола безубыточности
    reconciler.py     разрешение неизвестных исходов
  bot/             Telegram-интерфейс (owner-only)
  web/             FastAPI-панель
  workers/         планировщик фоновых задач
```

## Что система не гарантирует

Прямо из аудита ТЗ, раздел «Что нельзя гарантировать»:

- стабильный автономный режим на Tonnel / MRKT / Portals без
  партнёрского API;
- отсутствие ограничений со стороны Telegram при автоматизации
  пользовательской сессии;
- полную кросс-рыночную историю продаж и синхронные floor-цены;
- покупку строго по увиденной цене и атомарную операцию
  «купил на A — продал на B»;
- доходность, факт продажи или ликвидность.

Финансовые расчёты — инженерная оценка, а не гарантия прибыли.

## Безопасность

- Доступ к боту fail-closed: пустой `OWNER_IDS` = бот не отвечает никому.
- Секреты в БД шифруются Fernet на `GIFT_SECRET_KEY`.
- Логи чистятся от токенов и хешей.
- Каждое значимое действие попадает в журнал аудита.
- Файл сессии Telethon равносилен входу в аккаунт — держите его
  на сервере с ограниченным доступом и используйте отдельный
  торговый аккаунт.
