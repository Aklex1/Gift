# Боевой режим на Portals и MRKT

По умолчанию бот торгует только на официальном маркете Telegram.
Этот документ — как включить реальную торговлю на Portals и MRKT,
и что при этом нужно понимать.

---

## Сначала — о рисках, без прикрас

У Portals и MRKT **нет публичного API для торговли и нет обязательств
по доступности**. Что это значит на практике:

- **Эндпоинты меняются без предупреждения.** Сегодня покупка идёт на
  `/nfts/buy`, завтра путь другой. Бот получит 404 и остановится —
  но если изменится не путь, а смысл поля, деньги могут уйти не туда.
- **Токен живёт часы.** Его придётся обновлять руками (для MRKT можно
  автоматизировать через `MRKT_INIT_DATA`).
- **Аккаунт могут заблокировать** за автоматизацию.
- **Идемпотентности нет.** Если ответ потерялся, бот не знает,
  прошла покупка или нет. Он не повторяет её вслепую, а идёт сверять
  инвентарь — но сверка возможна только если чтение инвентаря работает.

Поэтому включение проходит через три независимых переключателя.
Случайно это не включается.

---

## Portals: подключение

Эндпоинты Portals известны и зашиты в бота, поэтому переносить их
из DevTools руками не нужно. И токен тоже: бот берёт его сам.

### Шаг 1. Токен — обычно ничего делать не надо

Токен Portals — это не постоянный API-ключ, а `initData`
мини-приложения: строка, которую Telegram выдаёт приложению при
открытии. Живёт она часы, поэтому «вписал один раз» не работает.

Бот открывает мини-приложение Portals сам, от имени вашего торгового
аккаунта (того, которым вы вошли через `gift-cli login`), и обновляет
строку каждые 6 часов, а при отказе площадки — сразу же. Отдельного
пароля для этого не нужно: сессия уже есть.

Состояние видно в панели: **Настройки → Токены площадок** — там же
кнопка «Продлить токены сейчас». То же самое из консоли:

```
gift-cli renew-tokens
```

Если продление не удастся, придёт уведомление в Telegram, и тогда
токен вписывают руками:

1. Откройте <https://web.telegram.org>, запустите в нём бота
   [@portals](https://t.me/portals) и его мини-приложение.
2. `F12` → вкладка **Network**.
3. Полистайте каталог, чтобы пошли запросы к `portals.tg`.
4. Кликните любой такой запрос → **Headers** → **Request Headers**.
5. Скопируйте значение `Authorization` **целиком, вместе с `tma ` в
   начале**. Выглядит так:

```
tma query_id=AAHdF6IQAAAAAN0XohDhrOrc&user=%7B%22id%22%3A...
```

Вставьте его в панели: **Настройки → Portals: Authorization**.

> Частая причина отказа — площадка переименовала мини-приложение.
> Лечится настройкой `PORTALS_MINIAPP` в формате `бот:короткое_имя`
> (по умолчанию `portals:market`). Бот на всякий случай пробует и
> второй способ — открыть приложение из кнопки меню бота, где
> короткое имя не нужно.

### Шаг 2. Включить в панели

Раздел **Торговля** (`http://<ip>:8081/trading`):

1. Режим — **SEMI**.
2. Переключатель **Portals** — включить.
3. **Лимит одной сделки** — например `2` TON.
4. **Применить**.

Перезапуск не нужен: значения лежат в общем хранилище и сразу
действуют в боте, воркере и панели. Аварийный стоп оттуда же
останавливает торговлю мгновенно во всех процессах.

Проверка готовности:

```bash
gift-cli contract portals
```

Команда ничего не покупает — только читает каталог, инвентарь и
показывает, какие операции открыты. Должно быть «готова к торговле
с подтверждением (SEMI)».

### Что уже настроено за вас

| Операция | Запрос |
|---|---|
| поиск | `GET /nfts/search` |
| инвентарь | `GET /nfts/owned` |
| баланс | `GET /users/wallets/` |
| история | `GET /market/actions/` |
| покупка | `POST /nfts` |
| выставление | `POST /nfts/bulk-list` |
| смена цены | `POST /nfts/{id}/list` |

Снятие с продажи Portals отдельным эндпоинтом не отдаёт — операция
`cancel` остаётся закрытой, пока вы не опишете её сами.

Если площадка сменит путь, поправьте его сами, не дожидаясь новой
версии бота: файл `markets/portals.json` перекрывает встроенные
значения поштучно.

```bash
gift-cli contract portals --template   # заготовка
nano /var/lib/gift/markets/portals.json
```

## Площадки без известного контракта: три шага включения

### Шаг 1. Доступ к площадке

В `/opt/gift/.env`:

```ini
# Portals
PORTALS_AUTH=tma query_id=AAH...

# MRKT — либо готовый токен,
MRKT_AUTH=eyJhbGci...
# либо initData: тогда бот сам получит токен и обновит по истечении
MRKT_INIT_DATA=query_id=AAH...&user=%7B%22id%22...
```

Где взять: откройте мини-приложение площадки в
[Telegram Web](https://web.telegram.org), `F12` → **Network**,
полистайте каталог, найдите запрос к API → **Headers** → скопируйте
`Authorization` целиком (для MRKT ещё можно взять `data` из запроса
`/auth` — это и есть initData).

Проверка, что чтение работает:

```bash
gift-cli contract portals
```

### Шаг 2. Контракт эндпоинтов

Бот не угадывает, как на площадке покупают — вы описываете это сами.
Создайте заготовку:

```bash
gift-cli contract portals --template
nano /var/lib/gift/markets/portals.json
```

Заполните по реальным запросам из DevTools. Пример **формата**
(пути подставьте свои — эти могут не совпадать с текущими):

```json
{
  "buy": {
    "method": "POST",
    "path": "/nfts/buy",
    "body": {"nft_details": [{"id": "{external_id}", "price": "{price}"}]},
    "success_when": {"field": "status", "equals": "ok"}
  },
  "list": {
    "method": "POST",
    "path": "/nfts/{external_id}/list",
    "body": {"price": "{price}"}
  },
  "cancel": {
    "method": "POST",
    "path": "/nfts/{external_id}/unlist"
  }
}
```

Подстановки:

| Шаблон | Во что превращается |
|---|---|
| `{external_id}` | идентификатор лота на площадке |
| `{price}` | цена в валюте площадки, например `2.5` |
| `{price_nano}` | та же цена в нанотонах, `2500000000` |

`success_when` — как понять по ответу, что операция прошла. Если его
не указать, успехом считается любой ответ 2xx. Если указанного поля
в ответе нет, исход считается **неизвестным** и уходит в сверку —
это безопаснее, чем угадывать.

Операции, которых нет в файле, остаются запрещёнными. Заготовка со
словом `ЗАПОЛНИТЕ` в пути не открывает ничего — так задумано.

### Шаг 3. Флаг и лимит

```ini
PORTALS_ENABLE_WRITE=true
PORTALS_MAX_TRADE_TON=3      # потолок одной сделки, в TON
```

Лимит обязателен: при `0` бот откажется считать площадку готовой.

Проверка перед первой сделкой:

```bash
gift-cli contract portals
```

Должно быть «✓ Площадка готова к торговле с подтверждением (SEMI)».
Команда ничего не покупает — только читает.

Перезапуск:

```bash
systemctl restart gift-bot gift-worker
```

## Настройка стратегии

Бюджет стратегии для Portals/MRKT должен вестись **в TON**, а не в
Stars — площадки торгуют за TON.

```sql
-- бюджет новой стратегии в TON
UPDATE budgets SET currency = 'TON', hard_cap = 20
WHERE name = 'budget:portals-flip';
```

В боте: **⚙️ Стратегии** → создать `/newstrategy portals-flip` →
задать бюджет → включить. В списке площадок стратегии должна быть
`portals`.

## Автономный режим

Пока всё вышеописанное включено, бот работает в **SEMI**: находит лот,
считает ROI и спрашивает подтверждение в Telegram. Каждая покупка —
ваше решение.

Чтобы он покупал сам:

```ini
DEFAULT_MODE=auto
AUTO_WHITELIST=telegram,portals
ALLOW_EXPERIMENTAL_AUTO=true
```

`ALLOW_EXPERIMENTAL_AUTO` — отдельный флаг именно потому, что это
качественно другой риск: между вами и ошибкой в контракте больше нет
человека.

**Не включайте это, пока не проведёте вручную хотя бы 10 сделок на
этой площадке и не убедитесь, что сверка инвентаря отрабатывает
корректно.**

---

## Что делает бот при каждой покупке

Порядок жёсткий и не меняется в боевом режиме:

1. Проверяет аварийный стоп, режим, флаг площадки и контракт.
2. **Перечитывает лот** и сверяет цену. Цена изменилась — отказ,
   к платёжному эндпоинту обращения не будет.
3. Проверяет лимит сделки в валюте площадки.
4. **Резервирует деньги в бюджете** — до внешнего вызова.
5. Отправляет запрос по вашему контракту.
6. Разбирает ответ:
   - успех → резерв списан, позиция открыта;
   - отказ → резерв освобождён;
   - **обрыв или непонятный ответ → статус UNKNOWN**, резерв
     удерживается, покупка **не повторяется**, запускается сверка
     по инвентарю.

Пункт 6 — причина, по которой чтение инвентаря обязательно. Без него
неизвестный исход невозможно разрешить.

---

## Аварийная остановка

```bash
# мгновенно, кнопкой «🛑 СТОП» в боте, либо:
systemctl stop gift-worker
```

Отключить только боевой режим площадки, оставив чтение цен:

```ini
PORTALS_ENABLE_WRITE=false
```

## Про Tonnel и Getgems

**Tonnel** — тот же механизм, но контракт пока не поддержан:
у площадки агрессивная защита Cloudflare, из-за которой даже чтение
часто не проходит. Включать торговлю там без стабильного чтения
бессмысленно.

**Getgems** — торговля требует подписи операции кошельком. Приватный
ключ бот не хранит и не должен хранить, поэтому автоматическая покупка
там невозможна без отдельного контура подписи (TON Connect или
внешний подписант). Это отдельная задача, в текущей версии не сделана.
