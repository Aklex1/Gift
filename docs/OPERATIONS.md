# Эксплуатация

## Первый запуск: порядок действий

1. `bash /opt/gift/deploy/install.sh` — установка в отдельный каталог.
   Порт 80 не занимается, другие сайты сервера не затрагиваются.
2. Заполнить `/opt/gift/.env` (см. [SETUP.md](SETUP.md)).
3. `gift-cli login` — авторизация торгового аккаунта.
4. `gift-cli doctor` — проверка. Должно быть «Критичных проблем нет».
5. `systemctl enable --now gift-bot gift-web gift-worker`
6. В боте: `/start` → **⚙️ Стратегии** → задать бюджет → включить.

Первые дни держите `DEFAULT_MODE=safe`: бот будет показывать находки,
не тратя деньги. Это лучший способ понять, адекватны ли оценки.

---

## Ежедневные проверки

```bash
systemctl status gift-bot gift-worker gift-web --no-pager
journalctl -u gift-worker --since "1 hour ago" | tail -50
gift-cli probe          # доступны ли площадки
```

В боте: **📊 PnL** и **💼 Портфель**.
В панели: раздел **Аудит** — там видны все операции.

## Типичные ситуации

### В .env нет настройки, о которой говорит документация

Установщик копирует `.env.example` только при первой установке и
рабочий файл потом не трогает, поэтому настроек из новых версий там
может не быть. Дописать недостающие, не трогая заданные значения:

```bash
gift-cli env-sync
```

`update.sh` вызывает эту команду сам, так что после обычного
обновления всё уже на месте.

### Панель отдаёт 502 Bad Gateway

502 означает, что nginx жив, а приложение за ним — нет. Разбор одной
командой:

```bash
bash /opt/gift/deploy/diagnose.sh
```

Скрипт покажет состояние сервисов, совпадение портов, ответ приложения
напрямую и журнал. Две самые частые причины:

1. **Порты разъехались** после обновления версии: приложение слушает
   один порт, nginx шлёт на другой. Лечится переустановкой юнитов:
   `bash /opt/gift/deploy/update.sh` — он переписывает юниты и конфиг
   nginx, сохраняя текущие порты.
2. **Сервис панели не запущен или падает.** Причина будет в журнале:
   `journalctl -u gift-web -n 30 --no-pager`.

### Бот не отвечает

Проверьте `OWNER_IDS`: при пустом значении бот молчит намеренно.
Узнайте свой id командой `/id` — она работает всегда.

### «Кандидатов нет»

Обычные причины, по порядку вероятности:

1. Не включена ни одна стратегия (**⚙️ Стратегии**).
2. У стратегии нулевой бюджет — включение блокируется.
3. Не хватает рыночных данных: `confidence = none`. Дайте боту
   поработать несколько часов, чтобы накопилась история.
4. Порог `MIN_ROI` выше, чем даёт рынок. 15% после 20% комиссии —
   это требование скидки около 35% от рыночной цены.

### FloodWait от Telegram

В логе `FloodWait N с`. Шлюз сам выдерживает паузу. Если повторяется —
увеличьте `SCAN_INTERVAL_SEC` и сократите список коллекций в стратегии.

### Площадка «отвалилась»

Токен приватного API протух. Получите новый (см. SETUP.md, п. 3) или
просто игнорируйте: на торговлю через Telegram это не влияет.

### Намерение зависло в UNKNOWN

Так и задумано: система не покупает повторно, пока не выяснит исход.
Воркер сверки пытается разрешить его каждые 2 минуты. После 8 неудачных
попыток запись попадает в лог с уровнем ERROR — тогда проверьте подарок
вручную в Telegram.

## Аварийная остановка

Любой из трёх способов:

```bash
# 1. Кнопка «🛑 СТОП» в боте — мгновенно, без перезапуска
# 2. Кнопка «Аварийный стоп» в веб-панели
# 3. Полная остановка сервисов:
systemctl stop gift-worker gift-bot
```

Для постоянного запрета впишите в `.env`:

```ini
KILL_SWITCH=true
```

## Резервное копирование

Критичны две вещи: база и файл сессии.

```bash
# БД
sudo -u postgres pg_dump gift | gzip > /root/gift-$(date +%F).sql.gz

# сессия и ключи
tar czf /root/gift-secrets-$(date +%F).tar.gz \
    /opt/gift/.env /var/lib/gift/trading.session
```

> `GIFT_SECRET_KEY` из `.env` необходим для расшифровки секретов в БД.
> Резервная копия базы без него бесполезна.

Восстановление:

```bash
gunzip -c /root/gift-2026-09-14.sql.gz | sudo -u postgres psql gift
```

## Как считается цена продажи

Репрайсер работает лестницей: выставляет выше рынка, затем шагами
снижает цену, но никогда не опускается ниже точки безубыточности.

Параметры стратегии:

| Поле | По умолчанию | Смысл |
|---|---|---|
| `sell_markup` | 0.25 | наценка над рыночной ценой на старте |
| `reprice_step` | 0.05 | на сколько снижать за шаг |
| `reprice_cooldown_h` | 12 | пауза между снижениями, часов |
| `floor_ratio` | 1.02 | минимальная маржа над безубыточностью |

Пример: купили на Portals за 3.9 TON, медиана рынка 4.5, floor 4.2.

```
Безубыточность при комиссии 2,5% : 4.05 TON
Ценовой пол (маржа 2%)           : 4.13 TON

Старт с наценкой 25%             : 5.62 TON
далее раз в 12 часов по −5%      : 5.33 → 5.06 → 4.80 → 4.56 → 4.33
ниже пола 4.13 не опускается     : ждём покупателя
```

С нулевой наценкой бот вместо этого подрезает floor на 1% и встаёт
первым в очереди на продажу — быстрее, но дешевле.

Полный проход лестницы при этих настройках занимает около трёх суток.
Чтобы продавать быстрее, уменьшите `sell_markup` и `reprice_cooldown_h`.

## Настройка комиссий

Значения по умолчанию — оценка. После первых реальных продаж
сверьте фактическое зачисление и поправьте:

```sql
-- посмотреть текущие
SELECT market, version, sale_fee, royalty, network_fee
FROM fee_schedules WHERE is_active = true;

-- новая версия комиссии (старую не удаляем — она нужна для истории)
INSERT INTO fee_schedules
    (market, version, sale_fee, buy_fee, royalty, network_fee, currency, is_active, note, created_at, updated_at)
VALUES
    ('telegram', 2, 0.22, 0, 0, 0, 'STARS', true, 'уточнено по факту продажи', now(), now());

UPDATE fee_schedules SET is_active = false WHERE market = 'telegram' AND version = 1;
```

Неверная комиссия — самая частая причина ложно прибыльных сделок.

## Включение автономного режима

Не раньше, чем наберётся статистика хотя бы по 10 закрытым сделкам
с положительным PnL.

```ini
DEFAULT_MODE=auto
AUTO_WHITELIST=telegram
MAX_TRADE_STARS=2000
DAILY_LIMIT_STARS=10000
MAX_OPEN_POSITIONS=5
```

`gift-cli doctor` откажется принимать в белый список что-либо, кроме
`telegram`. Следите за разделом **Аудит** первые сутки.

## Резервные копии и ключ шифрования

Копии снимаются таймером `gift-backup.timer` каждую ночь; `gift-cli doctor`
предупредит, если свежей копии нет больше трёх дней.

```
systemctl list-timers gift-backup        # расписание
bash /opt/gift/deploy/backup.sh          # копия прямо сейчас
gift-cli verify-key                      # ключ подходит к секретам?
gift-cli rotate-key --dry-run            # что будет перешифровано
bash /opt/gift/deploy/restore.sh ПУТЬ    # восстановить из копии
```

Подробности и порядок восстановления — [BACKUP.md](BACKUP.md).

Одно действие остаётся за вами: забрать копию `GIFT_SECRET_KEY` с
сервера и хранить отдельно. Без него копия базы — просто зашифрованный
мусор.

## Токены площадок

Токены Portals и MRKT — это `initData` мини-приложений, они живут часы.
Бот продлевает их сам: каждые полчаса проверяет возраст и, если строке
больше 6 часов, открывает мини-приложение от имени торгового аккаунта.
Плюс продление «по факту» — когда площадка ответила 401.

```
gift-cli renew-tokens          # продлить немедленно
```

Панель: **Настройки → Токены площадок** — возраст каждой строки и
кнопка продления.

Если продление не удалось, приходит уведомление (вид `token`). Разбор:

| Симптом | Причина | Что делать |
|---|---|---|
| `AUTH_KEY_UNREGISTERED`, «сессия не авторизована» | торговый аккаунт вышел | `gift-cli login` |
| `BOT_APP_INVALID` в обеих попытках | площадка переименовала приложение | задать `PORTALS_MINIAPP` / `MRKT_MINIAPP` как `бот:короткое_имя` |
| `FLOOD_WAIT_x` | слишком частые запросы к Telegram | подождать, продление повторится по расписанию |
| Продлилось, но площадка всё равно 401 | изменился формат заголовка | вписать `Authorization` вручную из DevTools |

Ручной токен не конфликтует с автопродлением: следующее удачное
продление просто заменит его свежим.

## Разница цен между площадками

По умолчанию **выключено**. Включается на странице «Торговля» →
«Разница цен между площадками».

Что бот делает: на каждом проходе сканера строит индекс цен по
«коллекция + модель» и ищет пары «купить здесь — продать там», где
разница переживает комиссию покупки, комиссию продажи, сетевые сборы
обеих площадок, стоимость переноса подарка и курс TON/Stars.

Что бот **не** делает: не исполняет эти сделки. Между покупкой и
продажей подарок нужно перевести на вторую площадку вручную. Это
минуты, и за это время цена там может уйти — поэтому связка остаётся
подсказкой, а решение за вами.

Два параметра:

| Параметр | Смысл | По умолчанию |
|---|---|---|
| Минимальная доходность | ниже какого ROI связки не показывать | 15% |
| Стоимость переноса | сетевая комиссия TON за transfer NFT | 0.1 TON |

Оба стоит уточнить по первому же реальному переносу: если он обошёлся
дороже, поднимите значение — иначе бот будет показывать связки,
которые на деле убыточны.

Результат — на странице «Кандидаты», отдельной таблицей над разбором
отсева. Читать её так: `Купить` — цена и площадка входа, `Продать` —
текущий минимум целевой площадки и сколько там всего лотов этого вида.
Если лотов один-два, цена там может быть случайной: проверьте руками,
прежде чем действовать.
