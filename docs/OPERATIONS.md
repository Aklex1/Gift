# Эксплуатация

## Первый запуск: порядок действий

1. `bash /opt/gift/deploy/install.sh` — установка в отдельный каталог.
   Порт 80 не занимается, другие сайты сервера не затрагиваются.
2. Заполнить `/opt/gift/.env` (см. [SETUP.md](SETUP.md)).
3. `gift-cli login` — авторизация торгового аккаунта.
4. `gift-cli doctor` — проверка. Должно быть «Критичных проблем нет».
5. `systemctl enable --now gift-bot gift-web gift-worker`
6. В боте: `/start` → **⚙️ Стратегии** → задать бюджет → включить.

Первые дни держите `DEFAULT_MODE=safe`: бот будет показывать находки,
не тратя деньги. Это лучший способ понять, адекватны ли оценки.

---

## Ежедневные проверки

```bash
systemctl status gift-bot gift-worker gift-web --no-pager
journalctl -u gift-worker --since "1 hour ago" | tail -50
gift-cli probe          # доступны ли площадки
```

В боте: **📊 PnL** и **💼 Портфель**.
В панели: раздел **Аудит** — там видны все операции.

## Типичные ситуации

### Бот не отвечает

Проверьте `OWNER_IDS`: при пустом значении бот молчит намеренно.
Узнайте свой id командой `/id` — она работает всегда.

### «Кандидатов нет»

Обычные причины, по порядку вероятности:

1. Не включена ни одна стратегия (**⚙️ Стратегии**).
2. У стратегии нулевой бюджет — включение блокируется.
3. Не хватает рыночных данных: `confidence = none`. Дайте боту
   поработать несколько часов, чтобы накопилась история.
4. Порог `MIN_ROI` выше, чем даёт рынок. 15% после 20% комиссии —
   это требование скидки около 35% от рыночной цены.

### FloodWait от Telegram

В логе `FloodWait N с`. Шлюз сам выдерживает паузу. Если повторяется —
увеличьте `SCAN_INTERVAL_SEC` и сократите список коллекций в стратегии.

### Площадка «отвалилась»

Токен приватного API протух. Получите новый (см. SETUP.md, п. 3) или
просто игнорируйте: на торговлю через Telegram это не влияет.

### Намерение зависло в UNKNOWN

Так и задумано: система не покупает повторно, пока не выяснит исход.
Воркер сверки пытается разрешить его каждые 2 минуты. После 8 неудачных
попыток запись попадает в лог с уровнем ERROR — тогда проверьте подарок
вручную в Telegram.

## Аварийная остановка

Любой из трёх способов:

```bash
# 1. Кнопка «🛑 СТОП» в боте — мгновенно, без перезапуска
# 2. Кнопка «Аварийный стоп» в веб-панели
# 3. Полная остановка сервисов:
systemctl stop gift-worker gift-bot
```

Для постоянного запрета впишите в `.env`:

```ini
KILL_SWITCH=true
```

## Резервное копирование

Критичны две вещи: база и файл сессии.

```bash
# БД
sudo -u postgres pg_dump gift | gzip > /root/gift-$(date +%F).sql.gz

# сессия и ключи
tar czf /root/gift-secrets-$(date +%F).tar.gz \
    /opt/gift/.env /var/lib/gift/trading.session
```

> `GIFT_SECRET_KEY` из `.env` необходим для расшифровки секретов в БД.
> Резервная копия базы без него бесполезна.

Восстановление:

```bash
gunzip -c /root/gift-2026-09-14.sql.gz | sudo -u postgres psql gift
```

## Настройка комиссий

Значения по умолчанию — оценка. После первых реальных продаж
сверьте фактическое зачисление и поправьте:

```sql
-- посмотреть текущие
SELECT market, version, sale_fee, royalty, network_fee
FROM fee_schedules WHERE is_active = true;

-- новая версия комиссии (старую не удаляем — она нужна для истории)
INSERT INTO fee_schedules
    (market, version, sale_fee, buy_fee, royalty, network_fee, currency, is_active, note, created_at, updated_at)
VALUES
    ('telegram', 2, 0.22, 0, 0, 0, 'STARS', true, 'уточнено по факту продажи', now(), now());

UPDATE fee_schedules SET is_active = false WHERE market = 'telegram' AND version = 1;
```

Неверная комиссия — самая частая причина ложно прибыльных сделок.

## Включение автономного режима

Не раньше, чем наберётся статистика хотя бы по 10 закрытым сделкам
с положительным PnL.

```ini
DEFAULT_MODE=auto
AUTO_WHITELIST=telegram
MAX_TRADE_STARS=2000
DAILY_LIMIT_STARS=10000
MAX_OPEN_POSITIONS=5
```

`gift-cli doctor` откажется принимать в белый список что-либо, кроме
`telegram`. Следите за разделом **Аудит** первые сутки.
