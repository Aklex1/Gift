# Настройка: какие данные нужны и куда их вписать

Все ключи живут в одном файле — `/opt/gift/.env` на сервере.
Открыть: `nano /opt/gift/.env`, после правок — `systemctl restart gift-bot gift-worker gift-web`.

---

## 1. API hash аккаунта для автоматического поиска подарков

Это главный вопрос. Поиск подарков идёт **не через бота**, а через
обычный аккаунт Telegram по протоколу MTProto — только он видит маркет
перепродажи.

### Где взять

1. Откройте <https://my.telegram.org> и войдите по номеру телефона
   того аккаунта, который будет торговать.
2. Раздел **API development tools**.
3. Создайте приложение (`App title` и `Short name` — любые, например
   `gift` / `gifttrader`).
4. Скопируйте два значения:
   - **App api_id** — число, например `21724531`
   - **App api_hash** — 32 символа, например `a1b2c3d4e5f6...`

### Куда вписать

Файл `/opt/gift/.env`, блок 3:

```ini
TG_API_ID=21724531
TG_API_HASH=a1b2c3d4e5f67890abcdef1234567890
TG_PHONE=+79991234567
```

### Авторизация сессии

api_hash сам по себе доступа не даёт — нужно один раз войти в аккаунт:

```bash
gift-cli login
```

Команда спросит код из Telegram и, если включена двухфакторная защита,
пароль. После успеха появится файл `/var/lib/gift/trading.session` —
это и есть доступ к аккаунту.

Проверка: `gift-cli whoami` покажет, под каким аккаунтом работает бот.

> **Заведите отдельный аккаунт под торговлю.** Файл сессии равносилен
> входу в аккаунт. Личный аккаунт использовать не стоит: автоматизация
> повышает риск ограничений со стороны Telegram.

## 2. Токен бота — интерфейс управления

Бот от @BotFather покупками **не занимается**, он только показывает
находки и принимает ваши подтверждения.

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Скопируйте токен вида `7123456789:AAF...`.
3. Впишите в `.env`:

```ini
BOT_TOKEN=7123456789:AAF_ваш_токен
```

### Свой Telegram ID

Доступ к боту закрыт по умолчанию: пока `OWNER_IDS` пуст, бот
**не отвечает никому**.

1. Запустите бота: `systemctl start gift-bot`
2. Напишите ему `/id` — он ответит вашим числовым id.
3. Впишите:

```ini
OWNER_IDS=123456789
```
4. `systemctl restart gift-bot`

Несколько владельцев — через запятую: `OWNER_IDS=123456789,987654321`

## 3. Аккаунты сторонних площадок (Portals, MRKT, Tonnel, Getgems)

### Честно о статусе

У Portals, MRKT и Tonnel **нет публичного API и нет SLA**. Работа с
ними идёт через приватные эндпоинты мини-приложений. Поэтому в системе
они имеют статус `experimental` и **покупка через них намеренно
отключена в коде** — используются только как источник цен для оценки.

Это не упущение, а осознанное решение: отправлять деньги в приватный
API без гарантий — прямой путь к их потере. Полный автоматический
режим на этих площадках возможен только после получения партнёрского
доступа.

### Как получить токен (если хотите видеть их цены)

Одинаково для Portals / MRKT / Tonnel:

1. Откройте мини-приложение площадки в **Telegram Web**
   (<https://web.telegram.org>).
2. `F12` → вкладка **Network**.
3. Поработайте в приложении — полистайте каталог.
4. Найдите любой запрос к API площадки → **Headers** → скопируйте
   значение заголовка `Authorization`.
5. Впишите в `.env` целиком, вместе со схемой:

```ini
PORTALS_AUTH=tma query_id=AAH...
MRKT_AUTH=Bearer eyJhbGci...
TONNEL_AUTH=Bearer eyJhbGci...
```

Токены протухают через несколько часов или дней. Это нормально: бот
пометит площадку недоступной, запишет это в журнал и продолжит работать
на Telegram. Проверить статус: `gift-cli probe` или страница
**Площадки** в веб-панели.

### Getgems

Единственная из внешних площадок с публичной документацией:
<https://api.getgems.io/public-api/docs>. Ключ запрашивается там же.

```ini
GETGEMS_API_KEY=ваш_ключ
```

Покупка через Getgems требует подписи кошельком, поэтому у нас
тоже только чтение.

## 4. TON (необязательно)

Нужен только для наблюдения за балансом кошелька.

1. <https://tonconsole.com> → **TON API** → создать ключ.
2. Впишите:

```ini
TONAPI_KEY=ваш_ключ
TON_WALLET_ADDRESS=UQ...ваш_адрес
```

> Приватный ключ кошелька в системе **не хранится и не требуется**.
> Расход TON бот делать не может — по проекту это отдельный контур
> через TON Connect или внешний подписант.

## 5. Предохранители — заполните до включения торговли

```ini
DEFAULT_MODE=safe        # начните только с safe
MAX_TRADE_STARS=5000     # потолок одной покупки
DAILY_LIMIT_STARS=20000  # потолок расходов за сутки
MAX_OPEN_POSITIONS=10    # сколько подарков держим одновременно
MIN_ROI=0.15             # минимум 15% чистыми после комиссий
AUTO_WHITELIST=          # пусто = автономный режим выключен
```

Значение `MAX_TRADE_STARS=0` означает «без предела» — так оставлять
нельзя. `gift-cli doctor` предупредит об этом.

## Проверка перед запуском

```bash
gift-cli doctor
```

Команда покажет, чего не хватает, и не даст запуститься с опасной
конфигурацией (например, с приватной площадкой в белом списке AUTO).
